# 往期报告存储说明

## 目标

往期报告必须持久化，但不能自动进入 OpenClaw 上下文。OpenClaw 只有在用户询问历史观点、需要对比或明确要求查看时，才调用报告工具读取。

## 保存流程

1. OpenClaw 生成当天日报。
2. 调用 `report_save` 或 HTTP `POST /api/v1/reports`。
3. 服务生成稳定 `report_id`。
4. 相同日期、类型、标题和来源重复保存时更新原记录。
5. 完整报告写入 SQLite。
6. `daily_report_context` 不包含任何往期报告全文。

## 列表流程

`report_list` 只返回报告目录字段：

- `report_id`
- 交易日期
- 标题
- 报告类型
- 涉及品种
- 短摘要
- 更新时间
- 字符数

列表不会返回完整报告内容。

## 读取流程

`report_read(report_id, offset, max_tokens)` 才会读取正文。单次默认最多返回 2,000 token，并返回：

- 本次正文片段。
- 本次 token 估算。
- 完整报告 token 估算。
- 是否截断。
- 下一次读取的 `next_offset`。

OpenClaw 需要继续阅读时，再用 `next_offset` 调用一次。

## 隔离规则

- 正常日报生成不自动读取往期报告。
- 不把全部历史报告拼接进提示词。
- 不在日报数据包中返回往期报告正文。
- 只有用户要求历史比较或模型确实需要时，才调用读取工具。
- 每份报告使用独立会话，日报完成后保存并归档。
